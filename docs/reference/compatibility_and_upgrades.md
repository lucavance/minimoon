# Compatibility and upgrades

Minimoon is pre-1.0. This policy defines the compatibility guarantees maintained
throughout the 0.1.x line.

## Compatibility surfaces

Applications import only `lampclaw/minimoon`. Its generated `src/pkg.generated.mbti`
is the public source-compatibility surface. Internal package names, normalized
trees, host commands, and generated helper functions are not public APIs.
Applications that explicitly import the optional `components`,
`components/styles`, or `testing` packages also treat their `.mbti` files as
public additive surfaces; existing static component and global testing methods
remain source-compatible throughout the 0.1.x line.

Generated applications have three versioned boundaries:

| Boundary | Current version | Rule |
| --- | ---: | --- |
| App Contract | 7 | CLI accepts and generates the current schema only |
| runtime ABI | 10 | runtime and host files must be generated together |
| renderer protocol | 7 | renderer commands and host decoder must match |

Generated files from different builds or versions must never be mixed. CommonJS
is the verified MiniApp host format for 0.1.x; ESM is not an implied upgrade.

## Version policy

- A 0.1.x patch must preserve the public root interface and all three protocol
  versions. It may fix behavior, improve internal performance, or change
  generated bytes. Changed bytes still require new real-host evidence.
- A future pre-1.0 minor may change the root interface or a protocol version,
  but must include a migration guide, update generated interfaces, rebuild every
  fixture, and invalidate prior host evidence explicitly.
- Internal packages carry no direct application compatibility promise. Their
  `.mbti` files are checked to detect accidental architectural drift.

The supported toolchain floor is `moon 0.1.20260827` with `moonc v0.10.11`.
Repository and generated-starter JavaScript tooling support Node `>=24.11.0`,
with CI coverage at the 24.11.0 lower boundary and in the 26.8.1 primary
environment; Bun is pinned to `1.4.0`. Raising any floor or pin requires
updating CI, the package consumer gate, starter guidance, and the compatibility
notes in one change.

## Upgrade procedure

1. Read `CHANGELOG.md` and any matching guide in `docs/guides/`.
2. Update the versioned `lampclaw/minimoon` dependency and run `moon update`.
3. Install the starter's exact JavaScript tooling dependencies.
4. Run `moon check --deny-warn` and application tests.
5. Rebuild the entire application in release mode; do not retain generated
   runtime, host, protocol, initial-tree, or page files from the prior version.
6. Run non-release verification, then validate the exact `dist/` in WeChat
   Developer Tools.
7. Record new evidence and run release verification only after the host pass.

Evidence uses the `fnv1a64-relpath-v2` boundary over complete distributable raw
bytes plus the generated manifest and smoke checklist. A checklist-only,
stylesheet, shared-template, or static-asset change therefore requires a new
host pass even when the versioned Contract/ABI/protocol numbers are unchanged.

Rollback means restoring both the source dependency and the complete generated
artifact set. Restoring only one helper file is unsupported.
